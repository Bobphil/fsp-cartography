# FSP-GOVERNANCE-RESIDUE-1

## Boundary Portability, Claim Ceilings, Authorization Separation, Remainder, Failure Routing, and Consequential Return

**Status:** GOVERNANCE RESIDUE / MINIMAL DISTINCTIVE ARCHITECTURE — VERSION 1
**Parents:** FSP-COMPARATOR-REGRESSION-1; FSP-CONSTITUTIONAL-COMPRESSION-1; FSP-CONSTITUTIONAL-REGRESSION-1; FSP-RECOMPOSITION-GOVERNANCE-1; FSP-RECOMPOSITION-ROUTING-REGRESSION-1
**Primary purpose:** Express the smallest defensible FSP governance architecture that survives four-comparator ablation and cross-domain regression.
**Primary claim ceiling:** This build identifies a minimal governance residue, not a final theory of inquiry, semantics, cognition, ontology, agency, or ethics.

# 1. The Residue

The comparator regression isolated the following surviving FSP function:

BOUNDARY PORTABILITY → CLAIM CEILING → AUTHORIZATION SEPARATION → REMAINDER VISIBILITY → FAILURE ROUTING → CONSEQUENTIAL RETURN

This build asks whether that residue can be compressed further without losing governance.

# 2. What the Residue Is Not

The governance residue is not a theory of truth, semantics, metaphysics, psychology, cognition, universal ontology, agency, ethics, causation, or optimal decision. It is a portable governance contract for carrying locally successful results across boundaries.

# 3. The Minimal Problem

Every serious inquiry eventually faces some version of LOCAL SUCCESS → USE ELSEWHERE.

The local success may be a measurement, model, inference, classification, diagnosis, historical reconstruction, simulation, policy result, or expert judgment.

The central FSP question is: **What survives when this result is carried somewhere else?**

# 4. Boundary Portability

A result is portable only insofar as the conditions that warranted it survive the crossing or are replaced by new warrant.

The crossing may change target, scale, representation, evidence type, population, institution, role, authority, time horizon, ontology, or practical stakes.

> **Local success ≠ portable warrant.**

# 5. Boundary Portability Is Not Boundary Suspicion

A boundary crossing is not itself a failure. A boundary is an inspection trigger, not a verdict.

The governance task is to test whether the warrant survives.

# 6. The Portability Test

1. What was established?
2. Where is it being carried?
3. What changed at the boundary?
4. Which warrant conditions still hold?
5. What no longer follows automatically?
6. What new burden appears?

If the relevant conditions survive, portability is preserved. If they do not, the result must be narrowed, supplemented, translated, or withheld.

# 7. Claim Ceiling

A Claim Ceiling states the strongest conclusion licensed by the current evidence and transition.

> **What does not yet follow?**

Examples: association ≠ causation; prediction ≠ mechanism; population estimate ≠ patient outcome; functional structure ≠ phenomenal identity; local policy success ≠ universal rule.

# 8. Claim Ceiling Is Not Mere Humility

A claim ceiling is tied to a specific transition. It is a portability limit on what may responsibly be asserted after a crossing.

# 9. Claim Ceiling and New Warrant

A claim may become stronger after recomposition only if new warrant is added.

> **Distance traveled does not increase warrant.**

> **Recomposition without new warrant cannot silently strengthen the claim.**

# 10. Authorization Separation

Even a well-supported claim may not authorize action.

> **Warranted judgment ≠ authorized intervention.**

Authorization may depend on consent, legal role, institutional authority, moral standing, jurisdiction, reversibility, proportionality, or affected-party rights.

# 11. Authorization Must Be Rechecked at Boundaries

Authorization does not automatically travel with knowledge.

Examples: engineer knows ≠ engineer authorizes launch; clinician recommends ≠ patient consents; researcher predicts ≠ regulator mandates; model classifies ≠ institution may sanction.

> **Authorization portability is independent of epistemic portability.**

# 12. Remainder

A Remainder is what the transition did not successfully carry.

It may include uncertainty, omitted variables, context, translation loss, unmodeled interaction, qualitative character, disagreement, unresolved standing, or untested consequences.

Remainder is not merely error. It is a governance output.

# 13. Remainder Visibility

> **What does not cross must remain visible.**

This protects against false closure, counterfeit completeness, overtranslation, overgeneralization, and forced ontology.

# 14. Remainder Can Increase

A crossing can create new uncertainty by introducing heterogeneity, translation loss, additional assumptions, or authorization problems.

> **Progress ≠ monotonic remainder reduction.**

# 15. Failure Routing

When portability fails, FSP should diagnose the mechanism rather than invent a generic label.

BOUNDARY ALARM → IDENTIFY WHAT CHANGED → SELECT FAILURE → APPLY TOOL / FIREWALL → SET CLAIM CEILING → CHECK AUTHORIZATION → PRESERVE REMAINDER → RETURN

# 16. Routing Families

Common routes include Map failure, Omission failure, Inferential overreach, Causal inflation, Background-condition blindness, Authority substitution, Judgment/authorization collapse, and Closure inflation.

The residue does not require new failure codes.

# 17. Failure Routing Is Not Failure Proliferation

> **Name the mechanism that broke, not merely the fact that a boundary was crossed.**

# 18. Consequential Return

A Return occurs when the result of inquiry or action re-enters lived Doing.

Return asks what changed, what worked, what failed, what burden appeared, what capability changed, who was affected, what must be repaired, and what must reopen.

# 19. Consequence and Return

The comparator regression identified a possible compression between Consequence and Return.

Could Consequence be absorbed entirely into Return? Partly.

Return already requires a changed situation. But without explicit consequence, Return risks becoming reflective rather than causal or practical.

> **Consequence is not an independent residue primitive, but it is an indispensable dimension of Return.**

Decision: compress Consequence into Consequential Return at the residue level.

# 20. Consequential Return

Consequential Return = changed situation + observed effects + revised capability + burden distribution + repair + REOPEN condition.

# 21. REOPEN and Return

REOPEN need not remain a separate residue item. It is the corrigibility condition of Return.

At the residue level, REOPEN is a condition within Consequential Return, though it remains separately named in pedagogy and applications because it is operationally important.

# 22. Partial Map Test

Partial Map remains constitutionally important, but it does not belong in the distinctive residue itself.

Simon explains partial problem representation; Price explains semantic/pragmatic plurality; Ismael explains situated mapping; Brandom explains scorekeeping maps.

> **Partial Map remains constitutional support, not governance residue.**

# 23. Relation Test

Relation is structurally necessary to define what is being carried and preserved, but it is not distinctively FSP.

> **Relation remains constitutional infrastructure, not governance residue.**

# 24. Transition Test

Transition remains the site where governance occurs, but Transition alone does no distinctive work.

At the residue level, Transition compresses into Boundary Portability.

# 25. License / Warrant Test

License/Warrant is necessary, but domain-native: inferential entitlement, calibration, causal support, consent, legal authority, translation fit, and more.

> **Warrant remains an input to portability testing, not a distinctive residue element.**

# 26. Governance Residue v2

After compression:

BOUNDARY PORTABILITY → CLAIM CEILING → AUTHORIZATION SEPARATION → REMAINDER VISIBILITY → FAILURE ROUTING → CONSEQUENTIAL RETURN

# 27. Can Boundary Portability and Claim Ceiling Merge?

No. Portability asks whether warrant survives the crossing; Claim Ceiling asks what the strongest surviving conclusion is.

# 28. Can Authorization Separation Merge into Claim Ceiling?

No. A claim ceiling constrains what may be asserted; authorization constrains what may be done.

# 29. Can Remainder Merge into Claim Ceiling?

No. A ceiling bounds the licensed conclusion; Remainder records what was not carried.

# 30. Can Failure Routing Merge into Boundary Portability?

Not fully. Portability identifies the crossing problem; routing identifies the failure mechanism and repair.

# 31. Can Consequential Return Merge with Remainder?

No. Remainder is unresolved content; Return is what happens when governed judgment or action re-enters the situation.

# 32. The Six-Role Residue

1. Boundary Portability
2. Claim Ceiling
3. Authorization Separation
4. Remainder Visibility
5. Failure Routing
6. Consequential Return

No further compression currently preserves all governance differences.

# 33. The Minimal Loop

LOCAL SUCCESS → BOUNDARY PORTABILITY TEST → CLAIM CEILING → AUTHORIZATION CHECK → ACT / WITHHOLD → CONSEQUENTIAL RETURN, with REMAINDER and FAILURE ROUTING available throughout.

# 36. Medicine Regression

Population evidence → patient.
Claim ceiling: estimate ≠ guaranteed patient outcome.
Authorization: recommendation ≠ consent.
Remainder: patient-specific interactions, values, long-term effects.
Failure routing: Omission Failure, Background-Condition Blindness, Judgment/Authorization Collapse.
Consequential Return: outcome updates diagnosis, plan, preference, and future options.

**PASS.**

# 37. Consciousness Regression

Neural and behavioral data → phenomenal claim.
Claim ceiling: structural constraint ≠ phenomenal identity.
Remainder: qualitative character and unresolved perspectival structure.
Failure routing: Inferential Overreach, Causal Confidence Inflation, Map Substitution.
Consequential Return: new experiments alter the constraint map and may shrink or reorganize remainder.

**PASS.**

# 38. Institutional Regression

Local safety success → institutional/regulatory policy.
Claim ceiling: local success ≠ universal policy.
Authorization: local expertise ≠ system-wide authority.
Remainder: context, exceptions, burden distribution, long-term effects.
Failure routing: Background-Condition Blindness, Aggregation Blindness, Judgment/Authorization Collapse, Closure Inflation.
Consequential Return: institutional effects reveal omitted coupling and may trigger policy REOPEN.

**PASS.**

# 39. Scientific Inquiry Regression

Measurement → model → explanation → ontology.
Claim ceiling: model success ≠ ontological identity.
Authorization: scientific success does not itself authorize social or technical intervention.
Remainder: alternative models, untested mechanisms, ontology uncertainty.
Failure routing: Inferential Overreach, Causal Confidence Inflation, Closure Inflation.
Consequential Return: new observations and failed predictions reopen the map.

**PASS.**

# 40. AI Regression

Task competence → epistemic authority → institutional delegation.
Claim ceiling: performance ≠ general reliability or understanding.
Authorization: recommendation ≠ authority to act.
Remainder: unknown failure modes, provenance, alignment with affected-party interests.
Failure routing: Map Substitution, Authority Substitution, Judgment/Authorization Collapse, Closure Inflation.
Consequential Return: deployment effects update authority, trust, scope, and REOPEN conditions.

**PASS.**

# 41. Cross-Domain Result

The six-role residue survives medicine, consciousness, institutions, scientific inquiry, and AI without requiring a new Core primitive, universal ontology, one warrant type, or one representational theory.

# 42. Distinctive FSP Claim

> **FSP is a governance architecture for testing the portability of local successes across changed boundaries, bounding what follows, separating warrant from authorization, preserving what does not cross, routing failures, and returning consequences into renewed inquiry.**

This should replace broader claims that FSP is itself a complete theory of cognition, inquiry, or meaning.

# 43. Architecture vs Theory

FSP should increasingly call itself a **transition-governance architecture** rather than a general philosophical theory.

# 44. Why This Matters

The residue provides a common governance layer without requiring one metaphysics, semantics, psychology, ontology, or scientific method.

# 45. Constitutional Layer vs Governance Residue

Constitutional infrastructure: Partial Map, Relation, Transition, warrant role, Return.

Distinctive governance residue: Boundary Portability, Claim Ceiling, Authorization Separation, Remainder Visibility, Failure Routing, Consequential Return.

The first is what FSP needs to operate. The second is what most clearly remains distinctive after comparator ablation.

# 46. Does This Replace FSP-CONSTITUTIONAL-COMPRESSION-1?

No. Constitutional Compression remains the broader operating architecture. Governance Residue identifies the smallest currently defensible distinctively FSP contribution.

# 47. Does This Replace the Failure Atlas?

No. Failure Routing depends on the Failure Atlas. The residue specifies when to route; the Atlas specifies failure mechanisms.

# 48. Does This Replace Tools?

No. Tools remain decompressions for investigating routed failures. The residue only needs a routing interface.

# 49. Does This Replace Domain Methods?

No. Medicine still needs medicine. Physics still needs physics. Ethics still needs substantive normative reasoning. Institutions still need organizational and legal analysis. FSP governs transitions among their outputs.

# 50. Formal Decompression Rule

Use the six-role residue in compressed form until the boundary is contested, the claim is consequential, authorization is disputed, remainder is decision-relevant, institutional amplification is likely, or failure diagnosis matters. Then decompress.

# 52. Strongest Supported Claim

> **After constitutional compression, object ablation, Simon comparison, near-decomposability stress, recomposition regression, Brandom integration, Price–Ismael situated pragmatism, and four-comparator ablation, FSP’s most defensible distinctive contribution can be compressed to six governance roles: Boundary Portability, Claim Ceiling, Authorization Separation, Remainder Visibility, Failure Routing, and Consequential Return. These roles govern how locally successful results move into new contexts without requiring a universal ontology, semantics, or theory of cognition.**

# 53. Claim Ceiling

This build does not establish that the six roles are historically novel, that no other framework contains equivalent functions, that six is finally minimal, that public users can reliably apply the six questions, that all inquiry is best modeled as boundary crossing, that authorization always follows inquiry, or that Return always reveals error.

# 54. REOPEN Conditions

Reopen this compression if:
1. one of the six roles can be removed without governance loss;
2. a cross-domain case repeatedly requires a seventh role;
3. Failure Routing proves derivative enough to remove;
4. Claim Ceiling can be fully reconstructed from portability + remainder;
5. Authorization Separation proves domain-local rather than portable;
6. Consequential Return can be reduced to ordinary feedback without loss;
7. public usability requires a different compression;
8. another framework supplies the same residue more parsimoniously.

# 57. Final Statement

The recent path has reduced FSP rather than enlarged it.

The current distinctive contribution can be stated in six questions:

> **Will the result travel?**
> **How far may the claim go?**
> **Who may act?**
> **What did not cross?**
> **What kind of failure occurred?**
> **What happened when the result returned to the world?**

In shortest form:

PORTABILITY → CEILING → AUTHORIZATION → REMAINDER → ROUTING → RETURN

That is the current FSP governance residue.
