## Certified production role

FSP-PROJECTION-PROFILES-1 converts the five ecosystem environments into executable production specifications.

A valid environment artifact must now pass through:

`canonical object → ecosystem binding → relation graph → projection profile → projection package → return`

The profile governs presentation and production. It does not become a second canonical authority.

## Certified profiles

Exactly one production profile is certified for each environment:

- `FSP-PROFILE-ENCYCLOPEDIA-1`
- `FSP-PROFILE-CLASSROOM-1`
- `FSP-PROFILE-VR-1`
- `FSP-PROFILE-APPLICATION-1`
- `FSP-PROFILE-RESEARCH-1`

Each declares:

- exposed canonical facets;
- hidden-by-default canonical facets;
- permitted transformations;
- required additions;
- optional additions;
- allowed relation types;
- required status markers;
- required return fields;
- return artifact type;
- forbidden mutations;
- completion criteria.

## Visibility firewall

Hiding a canonical facet does not delete or weaken it.

A profile may suppress a field from the immediate human interface for task fit, but canonical data remain upstream and recoverable.

Environment additions remain metadata and do not enter the canonical fingerprint.

## Claim-ceiling protection

Every certified profile explicitly forbids mutation of the canonical claim ceiling.

Every production package must preserve:

- canonical reference;
- canonical fingerprint;
- applicable canonical claim ceiling.

## Encyclopedia profile

The Encyclopedia profile permits plain-language transformation, progressive disclosure, and explanatory annotation.

It requires:

- chapter origin;
- reader depth;
- plain-language summary;
- canonical/projection status marker;
- probe/history status marker;
- exact prose/public-context return.

It may not create new routing authority or inflate canonical claims.

## Classroom profile

The classroom profile permits scaffolding, sequencing, plain-language rewriting, and instructional annotation.

It requires:

- learning objective;
- estimated time;
- student prompt;
- output-card schema;
- scaffold/canonical distinction;
- student-authored/system-supplied distinction.

Required return fields:

- student claim;
- student reason;
- remaining uncertainty;
- REOPEN condition.

A classroom artifact is not production-complete if the system supplies the learner's final judgment.

## VR profile

The VR profile permits:

- spatialization;
- temporal replay;
- perspective shift;
- progressive disclosure;
- status annotation.

It requires:

- scene ID;
- spatial layout;
- interaction primitives;
- persistent simulation status;
- debrief schema.

Required status firewalls:

- simulation ≠ history;
- perspective ≠ person;
- spatial relation ≠ semantic relation.

The VR return artifact is a non-immersive authorial debrief.

A VR artifact is not production-complete if it ends inside immersion or if immersive salience raises evidential standing.

## Application profile

The application profile permits domain binding and governance annotation.

It requires:

- target domain;
- domain authority;
- affected parties;
- permissions model;
- contestability path;
- transfer limitations.

Required status firewalls:

- analogy ≠ domain evidence;
- possibility ≠ recommendation;
- recommendation ≠ authorization.

The return artifact must be domain-owned and must identify judgment ownership, decision authority, affected-party review, remaining uncertainty, and REOPEN.

## Research profile

The research profile permits instrumentation, aggregation, comparison, and audit annotation.

It requires:

- study ID;
- hypothesis;
- measures;
- comparison condition;
- failure criteria;
- analysis plan.

Required status firewalls:

- measure ≠ construct;
- performance ≠ validity;
- result ≠ authorization.

Research artifacts must record failure and limitations and may not certify the FSP ontology.

## Projection package compiler

The certified compiler fails closed when required additions or status markers are absent.

A compiled package includes:

- canonical fingerprint;
- applicable claim ceiling;
- visible/hidden facets;
- transforms;
- overlays;
- affordances;
- presentation;
- environment additions;
- status markers;
- relation traversal permissions;
- required return artifact;
- forbidden mutations;
- completion criteria.

## Claim ceiling

This certification establishes production requirements for cross-environment FSP artifacts.

It does not prove that the profiles are optimal for learning, VR cognition, societal application, or research validity. It does not establish that every visibility decision is permanently correct.

Those choices remain REOPENable through empirical and philosophical testing.
