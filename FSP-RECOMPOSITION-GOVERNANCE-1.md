# FSP-RECOMPOSITION-GOVERNANCE-1

## Local Validity, Boundary Crossing, Recomposition Burden, Failure Routing, and Return

**Status:** CONSOLIDATION / META-GOVERNANCE BUILD — VERSION 1  
**Parents:** FSP-NEAR-DECOMPOSABILITY-STRESS-1; FSP-CONSTITUTIONAL-COMPRESSION-1; FSP-CONSTITUTIONAL-REGRESSION-1; FSP-CT-CANONICAL-1.1  
**Primary purpose:** Determine whether Bad Recomposition requires a new canonical Failure Atlas entry or should instead function as a cross-boundary routing pattern over existing failures.  
**Primary decision:** Do **not** add CT-F17. Treat recomposition as a meta-governance pattern that routes a boundary crossing toward existing failures, Firewalls, Tools, claim ceilings, and REOPEN.  
**Primary claim ceiling:** This document does not establish a universal theory of recomposition, a scalar metric of bridge burden, or a complete taxonomy of all cross-boundary inference. It consolidates the current architecture around already-frozen failure modes.

---

# 1. Why Recomposition Needs Governance

The near-decomposability stress test found a recurring pattern.

Local analysis can be valid.

The failure may appear only when that local result is carried into another:

- scale;
- target;
- representation;
- role;
- institution;
- population;
- patient;
- ontology;
- phenomenological claim;
- authorization context;
- time horizon.

This can be represented as:

```text
LOCAL MAP
→ LOCAL WARRANT
→ LOCAL RESULT
→ BOUNDARY CROSSING
→ RECOMPOSED CLAIM / ACTION
```

The key question is not merely:

> Was the local result correct?

It is:

> **What changed when that result crossed the boundary?**

This is the recomposition problem.

---

# 2. Recomposition Defined

A **recomposition** occurs when a result produced within one bounded decomposition is carried into a larger, different, or reassembled context.

Examples:

- engineering evidence → launch decision;
- population estimate → patient recommendation;
- local policy success → system-wide rule;
- neural correlate → phenomenal claim;
- organism adaptation → general theory of agency;
- historical analogy → universal philosophy-of-science claim.

Recomposition is not inherently illegitimate.

It is often necessary.

The governance problem is whether the local warrant survives the crossing.

---

# 3. Recomposition Is Not a New Primitive

The constitutional Core already contains what recomposition requires:

```text
Relation
Transition
Target Binding
Bridge Burden
Claim Ceiling
Remainder
Authorization
Consequence
REOPEN
Return
```

Therefore:

> **Recomposition ≠ new constitutional object.**

It is a recurrent configuration of existing transition-governance elements.

---

# 4. Why Bad Recomposition Should Not Become CT-F17

The frozen Failure Atlas already contains sixteen failure modes.

The strongest candidate overlaps are:

- CT-F01 Map Substitution;
- CT-F02 Omission Failure;
- CT-F03 Inferential Overreach;
- CT-F07 Authority Substitution;
- CT-F09 Aggregation Blindness;
- CT-F10 Causal Confidence Inflation;
- CT-F11 Background-Condition Blindness;
- CT-F15 Judgment/Authorization Collapse;
- CT-F16 Closure Inflation.

A new CT-F17 would create several problems.

## 4.1 It would duplicate multiple existing failures

Bad recomposition is not one failure mechanism.

It is a boundary condition under which different failures can occur.

## 4.2 It would weaken routing specificity

Saying “Bad Recomposition” does not yet tell the user what went wrong.

The real failure may be:

- overreach;
- target drift;
- omission;
- causal inflation;
- authorization collapse;
- closure.

## 4.3 It would violate the anti-proliferation rule

A new failure code should be added only if no existing failure set can diagnose the recurrent breakdown.

That condition is not met.

### Decision

> **Bad Recomposition = routing pattern, not canonical failure code.**

# 5. Recomposition Routing Pattern

The new governance pattern is:

```text
LOCAL RESULT
↓
BOUNDARY IDENTIFICATION
↓
WHAT CHANGED?
↓
ROUTE TO EXISTING FAILURE(S)
↓
APPLY FIREWALL / TOOL
↓
SET CLAIM CEILING
↓
PRESERVE REMAINDER
↓
CHECK AUTHORIZATION
↓
RETURN
```

This preserves the frozen Failure Atlas while strengthening cross-boundary diagnosis.

---

# 6. The Boundary Question

Every recomposition should begin with:

> **What boundary is being crossed?**

Candidate boundary types include:

- target boundary;
- scale boundary;
- representation boundary;
- evidence boundary;
- person/population boundary;
- model/world boundary;
- functional/phenomenal boundary;
- local/institutional boundary;
- judgment/action boundary;
- present/future boundary;
- one ontology/another ontology boundary.

The boundary type does not determine the failure.

It tells us where to inspect.

---

# 7. The Carry-Forward Question

The next question is:

> **What is being carried across?**

Examples:

- a measurement;
- a correlation;
- a causal interpretation;
- a risk estimate;
- a classification;
- a model;
- a historical analogy;
- a moral judgment;
- a recommendation;
- a local policy result.

This helps identify what must retain warrant after crossing.

---

# 8. The Survival Question

The third question is:

> **Which parts of the original warrant survive the crossing?**

A local warrant may depend on:

- target definition;
- scale;
- measurement conditions;
- background assumptions;
- population characteristics;
- institutional context;
- temporal horizon;
- consent;
- role authority.

If those conditions change, the original warrant cannot simply be inherited.

Thus:

> **Local validity ≠ inherited validity after recomposition.**

---

# 9. Recomposition Burden

A recomposition is high-burden when the crossing changes one or more of:

- target;
- scale;
- evidence type;
- causal structure;
- authority;
- affected parties;
- reversibility;
- time horizon;
- ontology;
- phenomenological interpretation.

This is not a scalar metric.

It is a typed burden profile.

> **High recomposition burden ≠ invalidity.**

But:

> **Hidden recomposition burden = governance risk.**

# 10. Recomposition Failure Family A — Map Substitution

## Pattern

A local representation is carried outward as though it were the larger reality.

## Canonical route

**CT-F01 — Map Substitution**

Examples:

- risk score → person;
- network metric → mind;
- local model → world;
- questionnaire score → whole experience.

## Firewall

> **Map ≠ World ≠ Person.**

---

# 11. Recomposition Failure Family B — Omission

## Pattern

The local decomposition was adequate only because certain relations were outside scope.

Recomposition silently treats those omissions as irrelevant.

## Canonical route

**CT-F02 — Omission Failure**

Examples:

- patient preferences omitted from population model;
- frontline burden omitted from policy metric;
- social context omitted from therapeutic outcome model.

## Diagnostic question

> What did the local map legitimately omit that the recomposed claim can no longer omit?

---

# 12. Recomposition Failure Family C — Inferential Overreach

A local conclusion becomes stronger after crossing than the evidence warrants.

> **Local success ≠ unrestricted generalization.**

# 13. Recomposition Failure Family D — Authority Substitution

# 14. Recomposition Failure Family E — Aggregation Blindness

# 15. Recomposition Failure Family F — Causal Confidence Inflation

---

# 16. Recomposition Failure Family G — Background-Condition Blindness

## Pattern

A local result is transferred into another context while the conditions that made it possible disappear.

## Canonical route

**CT-F11 — Background-Condition Blindness**

Examples:

- local safety success → universal regulation;
- controlled trial → routine practice;
- laboratory result → field outcome.

## Diagnostic question

> Which enabling conditions traveled with the result, and which did not?

---

# 17. Recomposition Failure Family H — Judgment/Authorization Collapse

# 18. Recomposition Failure Family I — Closure Inflation

# 19. Target Drift as a Routing Condition

Target drift is not currently a canonical Failure Atlas item.

It is better treated as a routing condition.

A target drifts when the analysis begins with one target and ends by making claims about another.

Examples:

```text
navigation
→ experience

population
→ patient

neural measure
→ identity

local process
→ institution
```

Target drift should route primarily to:

- CT-F01 Map Substitution;
- CT-F02 Omission Failure;
- CT-F03 Inferential Overreach.

And where action follows:

- CT-F15 Judgment/Authorization Collapse.

### Decision

> **Target Drift = routing condition, not new Failure Atlas code.**

---

# 24. Recomposition Governance Protocol

A bounded protocol can now be frozen.

## Step 1 — State the local result

What was actually established?

## Step 2 — Name the boundary

What scale, target, role, representation, or action context changes?

## Step 3 — List carried relations

What must remain true after the crossing?

## Step 4 — List dropped conditions

What was local, contextual, provisional, or omitted?

## Step 5 — Route failure risk

Which existing CT-F failure modes are now vulnerable?

## Step 6 — Apply claim ceiling

What does not yet follow?

## Step 7 — Check authorization

Who may recommend, decide, classify, constrain, or intervene?

## Step 8 — Preserve remainder

What uncertainty or untranslated content remains?

## Step 9 — Return

What consequence would show that the recomposition was inadequate?

---

# 25. Public Compression

The protocol should not appear to ordinary users as nine technical steps.

Public version:

> **What did we establish here?**

> **What changes when we carry it there?**

> **What no longer follows automatically?**

> **Who is allowed to act on it?**

> **What would make us reopen the move?**

This is sufficient for classroom and public-reader use.

# 34. Recomposition and Firewalls

Existing Firewalls already govern the main recomposition risks.

Examples:

> **Map ≠ World.**

> **Origin ≠ validity.**

> **Model success ≠ ontology.**

> **Benefit ≠ authorization.**

> **Shared representation ≠ shared ontology.**

> **Capability ≠ standing.**

> **Current judgment ≠ final closure.**

The recomposition layer does not need its own universal Firewall.

Its governing question is:

> **Does the warrant survive the boundary crossing?**

---

# 35. Recomposition and Claim Ceilings

Claim ceilings are especially important after recomposition.

A local result should acquire no stronger ceiling merely because it travels farther.

Instead:

```text
local result
+ boundary crossing
→ same or tighter ceiling
unless new warrant is added
```

This yields a strong governance rule:

> **Distance traveled does not increase warrant.**

And:

> **Recomposition without new evidence cannot silently strengthen the claim.**

---

# 36. Recomposition and Remainder

Recomposition often creates new remainder.

Examples:

- local context lost;
- subgroup heterogeneity introduced;
- translation uncertainty added;
- authority ambiguity created;
- phenomenal content left unresolved.

Therefore:

> **Remainder can increase during recomposition.**

This is important.

Progress does not require monotonic remainder reduction.

---

# 37. Recomposition and Authorization

Authorization must be rechecked when the boundary changes.

A person or institution authorized to make one kind of judgment may not be authorized to make another.

Examples:

- scientist → policymaker;
- clinician → patient decision;
- engineer → launch authority;
- model developer → regulator;
- researcher → identity-shaping intervention.

Thus:

> **Authorization does not automatically travel with epistemic output.**

This is a major recomposition rule.

---

# 38. Recomposition and Return

Return provides the strongest empirical check.

A recomposed intervention may reveal:

- omitted coupling;
- wrong target binding;
- unanticipated burden;
- capability loss;
- institutional distortion;
- failed generalization.

Therefore:

> **Return tests whether the recomposition preserved what mattered.**

If not:

```text
consequence
→ diagnose failure
→ reopen boundary assumptions
→ revise decomposition or recomposition
```

# 41. Failure Atlas Decision

## Decision

**DO NOT ADD CT-F17.**

Instead add a future Failure Atlas cross-cutting index entry:

### Recomposition Risk

**Symptom:** A locally supported result is being carried into a different target, scale, representation, institution, or action context.

**Diagnostic question:** What changed at the boundary, and which part of the original warrant no longer travels automatically?

**Routes to:** CT-F01, F02, F03, F07, F09, F10, F11, F15, F16 as appropriate.

This would be an **index/routing overlay**, not a seventeenth canonical failure.

# 42. Relation Graph Decision

Recomposition does not require a new semantic edge type by default.

Existing graph rules already prevent adjacency from becoming:

- identity;
- evidence;
- recommendation;
- authorization.

A recomposition view may traverse existing typed edges while exposing boundary changes.

### Decision

> **No new Relation Graph edge type until a concrete case demonstrates missing semantics.**

# 43. Canonical Compression Decision

The constitutional compression survives again.

Bad Recomposition does not expose a missing primitive.

It exposes a recurring **composition of existing failures** at boundary crossings.

This is exactly the kind of result the anti-proliferation architecture was designed to detect.

---

# 44. Strongest Supported Claim

> **Recomposition is a recurrent governance problem but not a distinct canonical failure mechanism. Across the tested cases, locally valid results become risky when carried across changed targets, scales, representations, authority structures, or action contexts. Those risks can be diagnosed more precisely by routing the crossing to existing FSP failures—especially Map Substitution, Omission Failure, Inferential Overreach, Authority Substitution, Aggregation Blindness, Causal Confidence Inflation, Background-Condition Blindness, Judgment/Authorization Collapse, and Closure Inflation—while preserving claim ceilings, remainder, authorization checks, REOPEN, and Return.**

---

# 45. Claim Ceiling

This build does not establish:

- that all recomposition failures reduce cleanly to the current nine routes;
- that no future CT-F17 will ever be needed;
- that boundary types can always be identified in advance;
- that recomposition burden can be quantified;
- that Return always reveals failure;
- that local validity guarantees anything about global validity;
- that all domain-specific overreach is merely recomposition.

---

# 46. REOPEN Conditions

Reopen this decision if:

1. a recurrent recomposition failure cannot be routed adequately to existing failures;
2. users systematically fail to diagnose recomposition without a dedicated canonical failure;
3. a new failure mechanism changes Tool routing, claim ceiling, or repair in a way current failures do not;
4. domain cases show that target drift or scale overreach are irreducible rather than routing conditions;
5. a Relation Graph implementation requires a distinct semantic relation for recomposition;
6. the routing overlay becomes more complex than a dedicated failure code would be.

# 52. Final Statement

The near-decomposability work revealed a real phenomenon.

But the right response is not another object.

It is better routing.

> **A locally warranted result does not carry its warrant automatically across a changed boundary.**

FSP should therefore govern recomposition by asking:

```text
WHAT WAS ESTABLISHED?
↓
WHAT BOUNDARY CHANGED?
↓
WHAT WARRANT STILL TRAVELS?
↓
WHICH EXISTING FAILURE IS NOW AT RISK?
↓
WHAT IS THE NEW CLAIM CEILING?
↓
WHO MAY ACT?
↓
WHAT REMAINS?
↓
WHAT WILL RETURN TELL US?
```

The resulting principle is:

> **Decompose for tractability. Recompose only with renewed warrant.**
