# FSP-FIREWALL-TOOL-PROVENANCE-LEDGER-1

## Canonical Encyclopedia Provenance Registry for Firewalls, Tools, Warrants, Cases, Evidence States, and REOPEN

**Status:** CANONICAL PROVENANCE LEDGER — VERSION 1  
**Purpose:** Make the historical, philosophical, scientific, formal, and case provenance of FSP Firewalls and Tools publicly inspectable.  
**Canonical relation:** This ledger supports, but does not replace, FSP-OUTWARD-VISION-ESSAY-2-FIREWALL-PROVENANCE.  
**Public-reader rule:** Human-readable names lead; internal IDs remain secondary.  
**Governance rule:** Firewall ≠ prohibition. A Firewall marks a transition that requires an additional warrant, evidential bridge, standing condition, or licensing argument.  
**Claim ceiling:** Historical recurrence + internal formalization + case stress-testing ≠ universal validity or empirical superiority.

---

# 1. Why a provenance ledger is needed

FSP should not ask readers to trust a finished vocabulary merely because the vocabulary appears coherent.

Every recurring Firewall and Tool should be answerable to questions such as:

1. What problem made this distinction necessary?
2. What recurrent failure does it block?
3. Where does the problem appear historically?
4. What additional warrant licenses crossing the gate?
5. Which Tool inspects the transition?
6. Which worked cases make the distinction concrete?
7. Has the distinction been formalized or tested?
8. What evidence state has actually been reached?
9. What would count against the present formulation?
10. What would REOPEN the Firewall or Tool itself?

This ledger therefore treats FSP concepts as **claims with provenance**, not as axioms.

# 2. Canonical entry schema

Every ledger entry uses the following fields.

| Field | Meaning |
|---|---|
| Stable key | Internal registry key for routing and versioning |
| Human-readable Firewall | Public-facing distinction |
| Protected transition | The move that must not occur silently |
| Recurrent failure | What goes wrong when the transition is treated as automatic |
| Historical / disciplinary provenance | Traditions, episodes, or problems that motivate the distinction |
| Crossing warrant | What additional evidence, reason, standing, or license could justify passage |
| Associated Tool / function | FSP inspection function |
| Worked cases | Cases currently used to expose or test the distinction |
| Formal implementation | Where the distinction enters executable schemas, state machines, or governance objects |
| Evidence state | Historical / conceptual / case / executable / human-validation status |
| Claim ceiling | What the current provenance does not establish |
| Failure conditions | What would count against the present formulation |
| REOPEN triggers | What would require revision, splitting, merging, or retirement |
| Canonical sources | Current FSP artifacts that own or substantiate the entry |

# 3. Evidence-state vocabulary

The ledger does not use a single undifferentiated word such as "validated."

## H — Historical / philosophical recurrence

The protected transition is visible in established historical, philosophical, scientific, or practical inquiry.

## C — FSP conceptual reconstruction

FSP has stated the distinction explicitly and connected it to a Tool, claim ceiling, or governance function.

## K — Worked-case stress

The distinction has been used in one or more worked cases.

## X — Executable / formal implementation

The distinction is represented in code, schemas, tests, formal translation objects, state machines, or regression gates.

## P — Protocol-ready human test

A human-validation protocol exists but has not yet produced independent-human evidence.

## E — External empirical support

Independent external evidence specifically supports the FSP operational claim.

**Current rule:** most ledger entries are H/C/K, selected entries are X, the translation program reaches P, and broad external effectiveness claims remain largely unestablished.

# 4. Ethical and human-inquiry Firewalls

## FW-01 — Map ≠ World ≠ Person

**Protected transition:** representation → represented reality / person.

**Recurrent failure:** a description, diagnosis, model, institutional record, ranking, statistic, or narrative is treated as though it exhausts the person or situation.

**Historical / disciplinary provenance:** phenomenological attention; philosophy of representation; measurement and model criticism; ethics of personhood; institutional classification.

**Crossing warrant:** triangulation among representations, direct engagement where possible, provenance, uncertainty, perspective recovery, and explicit acknowledgment of what remains outside the map.

**Associated Tool / function:** Attention / First Map Audit.

**Worked cases:** Ethics Ch1; resident representation in Gulf Pines; scientific observation and modeling throughout the Inquiry sequence.

**Formal implementation:** representation/source typing; provenance; translation remainder; state/history separation in FSP Cartography and translation layers.

**Evidence state:** H / C / K / X.

**Claim ceiling:** better representation ≠ final judgment; representation governance ≠ direct access to reality.

**Failure conditions:** the distinction becomes so broad that no representation can support action; "map" becomes a vague synonym for everything cognitive.

**REOPEN triggers:** domains where map/world/person distinctions distort rather than clarify; evidence that personhood language is inapplicable to a target domain; new representation types requiring finer distinctions.

**Canonical sources:** FSP-CT-ETHICS-1; FSP-CT-INQUIRY-1; FSP-TRANSLATION-1; FSP-JTS-INTEGRATION-GATE-1.

## FW-02 — Authority approval ≠ sufficient justification

**Protected transition:** authority endorsement → justified claim.

**Recurrent failure:** law, tradition, status, office, or confidence substitutes for reason-giving.

**Historical / disciplinary provenance:** Socratic examination; Plato's Euthyphro problem; argumentation theory; modern legitimacy disputes.

**Crossing warrant:** reasons independent enough to explain why the authority ought to approve or promulgate the claim.

**Associated Tool / function:** Examination / Reason-Giving Audit; Direction-of-Justification Test.

**Worked cases:** Ethics Ch2 "Law and the Direction of Justification."

**Formal implementation:** claim/warrant decomposition in FSP translation formalism.

**Evidence state:** H / C / K / X.

**Claim ceiling:** failure of an authority-based justification ≠ proof of the opposite conclusion.

**Failure conditions:** the Firewall is read as "authority never supplies evidence" rather than "authority alone is insufficient."

**REOPEN triggers:** domains where constitutive authority partly creates the relevant status and the current formulation under-describes that fact.

**Canonical sources:** FSP-CT-ETHICS-1; FSP-PRESSBOOK-INSTRUCTOR-IMPLEMENTATION-GUIDE-1; FSP-TRANSLATION-1.

## FW-03 — Formation ≠ justification

**Protected transition:** causal / developmental history → normative warrant.

**Recurrent failure:** explaining how a belief, habit, value, or practice formed is treated as proving it right or wrong.

**Historical / disciplinary provenance:** Aristotle on habituation and practical formation; genealogy; sociology of knowledge; developmental and institutional accounts.

**Crossing warrant:** independent reasons, evidence, or normative premises connecting formation history to present justification.

**Associated Tool / function:** Formation / Practical-Wisdom Audit.

**Worked cases:** Ethics Ch3; later genealogical comparisons.

**Formal implementation:** assembly-history fields remain distinct from claim ceilings and warrants.

**Evidence state:** H / C / K.

**Claim ceiling:** good formation ≠ complete moral warrant; bad origin ≠ present invalidity.

**Failure conditions:** the distinction blocks legitimate evidential relevance of formation history.

**REOPEN triggers:** cases where formation itself is constitutive of the norm and requires a more qualified gate.

**Canonical sources:** FSP-CT-ETHICS-1; FSP-PRESSBOOK-INSTRUCTOR-IMPLEMENTATION-GUIDE-1.

# 5. Scientific and historical-inquiry Firewalls

**Recurrent failure:** calibration, transformation, noise modeling, and interpretation disappear.

**Historical / disciplinary provenance:** Galileo; Foucault; metrology; experimental science.

**Crossing warrant:** calibration chain, measurement model, uncertainty, reproducible procedure, provenance.

**Associated Tool / function:** Measurement / Provenance Audit.

**Worked cases:** Galileo; Foucault light-speed measurement.

**Formal implementation:** observation vs inference typing; source ledgers; provenance objects.

**Evidence state:** H / C / K / X.

**Failure conditions:** the distinction becomes constructivist overreach denying robust measurement.

**REOPEN triggers:** instruments or automated pipelines where current provenance fields are insufficient.

**Historical / disciplinary provenance:** translation theory; Kuhnian change; interdisciplinary modeling; pluralism.

**Associated Tool / function:** Translation / Remainder Audit.

# 9. Provenance integrity rules

The public Encyclopedia should obey these rules.

1. **Historical actor ≠ FSP user.**  
   Socrates, Aristotle, Kuhn, Duhem, Einstein, Smith, Rawls, or others are not retroactively described as using FSP Tools.

2. **Lineage ≠ ownership.**  
   A historical tradition can motivate a Firewall without being reducible to it.

3. **Case use ≠ validation.**  
   A case can expose usefulness without proving generality.

4. **Executable test ≠ external effectiveness.**  
   Passing regression tests establishes internal conformance, not social benefit.

5. **Protocol readiness ≠ human validation.**  
   FSP-TRANSLATION-12 remains PENDING until independent coders exist.

6. **Comparator portability ≠ universality.**  
   Gulf Pines and Asteria support portability claims only within tested topologies.

7. **Remainder ≠ escape hatch.**  
   Repeated untranslatability must count against the formalism.

8. **Claim ceiling applies to the ledger itself.**  
   The ledger is a current reconstruction and can be revised.

# 12. Development protocol for adding a new Firewall

A new Firewall should not be added because a phrase sounds useful.

Required dossier:

1. **Candidate transition**
2. **At least two materially different failure cases**
3. **Evidence that the transition can sometimes be licensed**
4. **Positive crossing warrant**
5. **Existing Tool fit or reason a new Tool is required**
6. **Claim ceiling**
7. **Remainder implications**
8. **At least one adversarial comparator**
9. **Failure conditions**
10. **REOPEN criteria**
11. **Canonical owner**
12. **Regression effect on existing Firewalls**

Decision outcomes:

- ADD
- MERGE WITH EXISTING
- SUBTYPE EXISTING
- KEEP DOMAIN-LOCAL
- REJECT
- PENDING EVIDENCE

# 13. Development protocol for adding or revising a Tool

A new Tool requires evidence that an existing Tool cannot inspect the recurring pressure without distortion.

Required questions:

1. What failure topology is not already covered?
2. Which historical/domain practices motivate the Tool?
3. Which Firewall(s) does it inspect?
4. What output does it produce that changes inquiry?
5. What is its claim ceiling?
6. When should it not be used?
7. Does it duplicate another Tool?
8. Can it be progressively disclosed?
9. Does it survive at least two domain-native cases?
10. What would retire it?

Tools therefore remain:

> **portable but non-sovereign operators.**

# 18. Final provenance principle

The deepest purpose of this ledger is not to prove that FSP invented every distinction it uses.

It is to make the opposite fact productive.

Human inquiry has spent centuries discovering places where one kind of evidence, reason, power, representation, or success does **not yet** license a stronger conclusion.

FSP treats those discoveries as reusable intellectual infrastructure.

A Firewall is therefore:

> **the memory of a transition that inquiry has learned not to cross silently.**

A Tool is:

> **a portable practice for inspecting why the transition is under pressure.**

A warrant is:

> **the positive license that can justify passage.**

A claim ceiling is:

> **the record of how far the present evidence has actually carried us.**

And REOPEN is:

> **the mechanism by which the gate itself remains corrigible.**

> **FSP-FIREWALL-TOOL-PROVENANCE-LEDGER-1: CANONICAL VERSION 1 — READY FOR ENCYCLOPEDIA BINDING.**
