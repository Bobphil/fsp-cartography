# FSP-LIVES-PUBLIC-ROUTE-1

## Public Lives-in-Transformation Route Specification

**Status:** PUBLIC-ROUTE SPECIFICATION — VERSION 1  
**Parents:** FSP-LIVES-IN-TRANSFORMATION-1; FSP-LIVES-IN-TRANSFORMATION-PILOT-1; FSP-LIVES-IN-TRANSFORMATION-ARISTOTLE-1; FSP-LIVES-IN-TRANSFORMATION-MANDELA-1; FSP-LIVES-IN-TRANSFORMATION-REGRESSION-1; FSP-RESEARCH-ENVIRONMENT-1  
**Primary purpose:** Define the public Encyclopedia route for Lives in Transformation using the three-case regression result: a common shell plus topology-sensitive optional modules.  
**Deployment status:** SPECIFICATION ONLY — NOT YET LIVE.  
**Primary claim ceiling:** This route specification defines presentation and navigation. It does not create new historical claims, strengthen dossier claims, or become a second owner of biographical content.

---

# 1. Governing Result

The public Lives route must implement:

> **COMMON SHELL + TOPOLOGY-SENSITIVE MODULES**

The route must not require every life to populate every field.

Missing modules may reflect:
- source limits;
- topology differences;
- historical irrelevance;
- deliberate claim ceiling.

A missing module is not a missing feature of the person.

---

# 2. Canonical Ownership

The public route owns:
- navigation;
- progressive disclosure;
- visual ordering;
- reader-depth behavior;
- return paths.

It does not own:
- source claims;
- state chronology;
- transition content;
- motive claims;
- claim ceilings;
- historical interpretation.

Those remain with the canonical dossier and domain sources.

---

# 3. Common Shell

Every public Lives dossier must expose the following route:

**PERSON  
→ STATES  
→ TRANSITIONS  
→ SOURCES  
→ CAPABILITY / CONSTRAINT  
→ HISTORICAL RETURN  
→ PORTABILITY**

This is the minimum public grammar.

---

# 4. Surface View

The first public view should answer:

1. Who is this person in this bounded historical inquiry?
2. What changed across time?
3. What are the major transitions?
4. What sources support the reconstruction?
5. What changed in capability or constraint?
6. What, if anything, might responsibly travel to another context?

The Surface view must not expose the full research schema.

---

# 5. Inspect View

The Inspect layer may expose:

- state cards;
- transition cards;
- source badges;
- capability / constraint deltas;
- institutional role;
- public artifacts;
- intended / actual contrast;
- failed or revised plan;
- authorization;
- strategy;
- concept / text development;
- counterfactual probe;
- claim ceiling;
- remainder.

Only modules warranted by the dossier may appear.

---

# 6. Deep View

The Deep layer exposes:

- source ledger;
- source class;
- chronology uncertainty;
- competing interpretations;
- motive ceiling;
- FSP inference labels;
- historical remainder;
- route provenance;
- REOPEN conditions.

Depth changes presentation density, not historical certainty.

---

# 7. Required Public Modules

The following are required for all Lives dossiers.

## Person Header

Display:
- name;
- bounded research question;
- date range;
- dossier status;
- dominant topology;
- claim ceiling.

## State Timeline

At least three bounded states where the source record permits.

A state may be low-density.

## Transition View

Each major transition must distinguish:
- documented change;
- inferred structural relation;
- unresolved motive / remainder.

## Source View

Every major public claim must be traceable to source type and ledger ID.

## Capability / Constraint View

Show only sourced or carefully bounded changes.

## Historical Return

What new situation existed after the transition?

## Portability Gate

What structural relation might travel?
What must not travel?

---

# 8. Optional Topology Modules

## Intended / Actual

Use when sufficient evidence exists for intended action or stated purpose.

## Failed Plan

Use only when a failed or revised plan is historically supportable.

## Strategy Revision

Use when strategic means change under altered constraints.

## Authorization / Standing

Use when power, role, legitimacy, consent, jurisdiction, or organizational authority materially structure the transition.

## Text / Concept Development

Use when intellectual development is better evidenced through texts, practices, or research programmes than through motive biography.

## Institutional Role

Use when institutional location changes capability, authority, or inquiry.

## Counterfactual Probe

Use only as a dependency test, never as alternate-history prediction.

---

# 9. Evidence-Density Display

The route must visibly distinguish:

- high-density state;
- medium-density state;
- low-density state.

Evidence density concerns the available record.

It does not measure the historical importance of the state.

Freeze:

> **Sparse evidence ≠ unimportant life period.**

---

# 10. Motive Display Rule

Public prose must distinguish:

- stated reason;
- contemporary interpretation;
- later retrospective explanation;
- biographer interpretation;
- FSP inference.

Never render inferred motive as direct psychological access.

---

# 11. Hindsight-Control Mode

Every public dossier should support a bounded historical mode when feasible.

In Hindsight-Control Mode:
- later outcomes are hidden;
- later fame is hidden;
- later canonical status is hidden;
- later political office is hidden;
- later interpretations are suppressed unless available at that time.

The reader receives:
- then-available evidence;
- live possibilities;
- constraints;
- uncertainty.

Freeze:

> **Later significance ≠ earlier foresight.**

---

# 12. Topology Profiles

## Maathai Profile

Primary modules:
- Intended / Actual;
- Failed Plan;
- Authorization / Standing;
- Institutional Role;
- Capability / Constraint;
- Hindsight Control.

Do not require:
- Text / Concept Development;
- Negotiation / Collective Authorization module.

## Aristotle Profile

Primary modules:
- Institutional Role;
- Text / Concept Development;
- Capability / Constraint;
- Hindsight Control;
- Evidence-Density warnings.

Do not require:
- Failed Plan;
- explicit motive;
- Authorization as dominant module.

## Mandela Profile

Primary modules:
- Strategy Revision;
- Authorization / Standing;
- Institutional Role;
- Capability / Constraint;
- Intended / Actual;
- Hindsight Control.

Do not require:
- Text / Concept Development;
- one discrete Failed Plan.

---

# 13. Public Reader Sequence

Default sequence:

**PERSON HEADER  
→ TIMELINE  
→ SELECT STATE  
→ SELECT TRANSITION  
→ INSPECT SOURCES  
→ INSPECT CAPABILITY / CONSTRAINT DELTA  
→ OPTIONAL TOPOLOGY MODULES  
→ HISTORICAL RETURN  
→ PORTABILITY GATE  
→ RETURN TO RESEARCH REGION**

Optional:

**→ LIFE NAVIGATION**

only if the reader explicitly chooses personal transfer.

---

# 14. Portability Gate

Before personal transfer, require:

1. structural relation;
2. contextual similarity;
3. contextual difference;
4. non-portable feature;
5. claim ceiling;
6. reversible test.

The route may not prefill a recommendation.

---

# 15. Life Navigation Handoff

Life Navigation remains optional.

The only permitted handoff prompt is structurally equivalent to:

> Do you want to examine whether one structural relation from this case applies to a situation of your own?

If declined:
- return to dossier.

If accepted:
- pass only the selected structural relation and claim ceiling.

Do not pass:
- historical person as model;
- recommendation;
- predicted future;
- assumed personal goal.

---

# 16. Public Firewalls

**Biographical dossier ≠ person.**  
**Later significance ≠ earlier foresight.**  
**Formation ≠ justification.**  
**Historical success ≠ recommendation.**  
**Admiration ≠ portability.**  
**Public role change ≠ proven private identity change.**  
**Missing field ≠ missing human feature.**

---

# 17. Semantic-Drift Failures

The public route fails if:

1. every dossier displays identical modules;
2. low-evidence states are visually presented as equally certain;
3. later outcomes leak into early-state view;
4. a motive inference appears as fact;
5. the route turns a life into a motivational template;
6. historical recognition becomes ethical validation;
7. optional Life Navigation becomes default;
8. public route creates its own claim ceiling;
9. topology modules proliferate into new canonical objects.

---

# 18. Acceptance Tests

The public Lives specification passes only if:

- Maathai can render without Aristotle-only modules;
- Aristotle can render without a failed-plan module;
- Mandela can render strategy and authorization without forcing Maathai's movement topology;
- all three preserve source traceability;
- all three preserve hindsight control;
- all three end with Return / portability rather than imitation.

---

# 19. Deployment Boundary

This specification does not authorize:
- site/index.html edits;
- new public hash routes;
- production UI;
- Life Navigation auto-linking;
- VR deployment.

Implementation must follow a separate executable route build.

---

# 20. Strongest Supported Claim

> **A public Lives-in-Transformation route can preserve a shared diachronic grammar across diverse historical lives while exposing only the topology-specific modules justified by each dossier. This allows comparison without flattening evidence density, motive certainty, institutional structure, strategy, or conceptual development into a single biography template.**

**PASS — RETAIN AS PUBLIC LIVES ROUTE SPECIFICATION.**
